# PLAN 接口与规划触发修复

实现阶段于 2026-10-24 完成离线验证，随后用于服务器隔离评测镜像 `sha256:44b4ed1d33fa4e6f9c65e2d1f04f4d38f5689f156bdbc108d6fe9c8a590c6f95`。2026-10-26 按证据读取、图发布协议、规划增量审查与说明文档分段发布；代码与该候选保持一致，本次发布不新增部署或在线测试。

## 修复范围

| 模式 | 证据发现与错误恢复 | 图发布与规划 |
| --- | --- | --- |
| Progressive | 默认启用现有 `planning_list_evidence`；精确 ID 读取失败返回目录指引 | 规划请求显示自上次接受审查以来的任务、证据、checkpoint 变化 |
| Hypothesis | 复用同一目录；显式关闭时错误指引使用仍可用的 board | 发布返回实际 cardId、完整 evidenceRefs；省略版本与空 resolutions 由宿主补齐；既有输入错误记录固定原因与字段；规划注入变化摘要 |
| Cairn | 保留现有 `graph_list_evidence`；缺失证据/图记录返回同 run 完整合法 ID 和正确查询入口 | 沿用已有 claim/ack reason-trigger 流程，不重做调度器 |
| Artex | 复用共享目录；图引用不存在时给出正确查询入口 | 发布返回实际 nodeId、完整 evidenceRefs；机械默认值与稳定幂等键；输入错误可纠正；规划注入变化摘要并消除自身记账引发的重复唤醒 |

配置默认打开目录，但保留明确的 `false`。批测 worker 不再无条件覆盖成关闭。目录关闭时共享读取失败最多返回 10 个同 run 完整有效 ID；不接受模糊或跨 run 引用。

Artex 省略 kind/confidence 时分别使用 fact/inferred，省略 key 时根据规范化输入生成稳定键。payload 与真实已持久证据仍由调用者选择，不自动绑定“最近输出”。hint 可省略无语义变化的空引用数组。所有模式保持原生校验为最终成功依据。

## 规划变化与唤醒

Progressive、Hypothesis、Artex 共用小型快照差量：任务状态、原始证据 ID、卡片 ID、worker 图节点、假设状态及 checkpoint ID。提示中每组至多呈现最近 16 项及省略数，ID 不截短。事件记录相同的呈现摘要；记录审查确认代表宿主接受了该请求的输入版本，不证明模型逐条阅读或采用了所有证据。

Artex 的唤醒状态不再依赖 run revision、图 version、TODO 或 planner hint。领租约等 active 状态之间的变化不单独唤醒；新证据、卡片、worker finding、checkpoint、任务终态和容量变化仍可唤醒，满槽复审仍保留。800ms 合并、600s 心跳不变。

只有接受的规划才推进当前 harness 内的已审基线。提交时仅补记规划器自身写入的差异；请求期间到达的 worker 更新留给下一轮。失败不推进。没有新增数据库表或持久游标；重启后首次审查重新取当前完整快照。

## 诊断与约束边界

既有输入拒绝分层为固定原因码和字段路径，覆盖 Artex/Hypothesis 发布、对应提案验证与缺失引用。Pi 原生参数校验的字段路径仅按可信 schema 提取。新增诊断不记录 prompt、工具输出正文、候选或凭据。

可恢复错误通过 Pi 原有 tool_result hook 设置错误标识，并在同一会话继续纠正。新分类的规划输入错误接入原有 harness 纠错路径，失败审查不确认待处理增量。存储、失效租约等错误继续上报。没有新增拒绝计数、提前结束条件、父节点限制、并发限制或独立模型循环。共享证据库、校验账本、假设图、产物路径逻辑保留。
